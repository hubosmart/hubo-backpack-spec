# Hubo-Tack 背包身份卡规范（SPEC-004 公开版 V2.2）

> **DIY 背包规则（必须遵守）**
>
> 1. **DIY 背包必须使用 0x57 烧录版身份卡**：`AT24C02` 的 `A0`～`A2` 全部接 `3V3`，写入 12 字节描述符。0x50～0x56 为官方型号保留，DIY 背包不得使用。
> 2. `product_id` 取 **DIY 号段 `0xF000`～`0xFFFE`**：自用、不保证全局唯一、无需申请。`0x0000`、`0xFFFF` 禁用。
> 3. 需要**全局唯一**的 `product_id`，通过 GitHub Issue 申请（见 4.2，使用 [Issue 模板](../../.github/ISSUE_TEMPLATE/product-id-request.md)）。
> 4. 烧写方法见第五章：用 hubo-backpack-skill 中的 `idcard_image.py` 生成 16 字节镜像，把 `WP` 测试点拉低，用通用 I²C EEPROM 烧录器写到 0x57 的偏移 0x00。
> 5. 主机固件对不认识的 `form_id` 按 0（不使用复用区）处理，不报错，所以 DIY 号段不需要固件改动。

> 本文是内部规范 SPEC-004 V2.2 的公开版，并并入了背包描述符的 12 字节格式与 `form_id` 取值（3.6、3.7）。章节与条款编号保持原样；内部流程类条款不随公开版发布，对应编号处标注“（本公开版不含）”。接口与机械要求见 [SPEC-003 公开版](./30pin-backpack-spec.md)。

## 一、适用范围

本规范适用于插接在 Hubo-Tack 主板（ESP32-P4）、S3 主机（ESP32-S3）、CM 系列（开发中）这三类主机 30-Pin 连接座上的全部 30-Pin 背包；规范以 Hubo-Tack 为基准。S3 主机目前不能识别按本规范做的身份卡（主板没有身份卡 I2C 上拉，固件只探测 0x50）；CM 系列开发中，以发布时为准。各主机差异见 [SPEC-003](./30pin-backpack-spec.md) 1.4。身份卡挂在主板的身份卡 I2C 总线上（`GPIO30`／`GPIO31`，背包焊盘 14 = `SCL`、15 = `SDA`，见 [SPEC-003](./30pin-backpack-spec.md) 3.1）。

本规范中的主机识别流程（扫描 0x50～0x57、读取并校验描述符）是对主机固件的要求；目前固件只实现了其中一部分（探测 0x50），完整流程在开发中。

## 二、地址规划

### 2.1 原则

1. **官方型号免烧录**：官方型号使用空白 `AT24C02`，主机按 7 位 I2C 地址区分型号；0x50～0x56 一个地址对应一个官方型号，保留给官方使用，DIY 背包不得使用（主机会按该地址对应的官方形态驱动复用区）。
2. **0x57 为烧录版**：烧录 12 字节描述符（含 `product_id`）。**DIY 背包一律使用 0x57**。
3. **主机识别流程**：扫描 0x50～0x57。恰好一个地址应答时：0x50～0x56 **不读描述符**，按官方型号处理；0x57 读 12 字节描述符并校验签名与 CRC。0x57 描述符校验失败、或有多于一个地址同时应答时，一律按 `form_id = 0x00`、`flags = 0`（复用区全高阻）处理，并分别上报“未知背包”或“背包地址冲突”。

### 2.2 地址分配表

| 地址 | A2 A1 A0 | 用途 | 主机处理 |
|---|---|---|---|
| 0x50 | 0 0 0 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x51 | 0 0 1 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x52 | 0 1 0 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x53 | 0 1 1 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x54 | 1 0 0 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x55 | 1 0 1 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| 0x56 | 1 1 0 | 官方型号保留 / Reserved for official models | 按官方型号处理 |
| **0x57** | 1 1 1 | **烧录版**（描述符 + `product_id`），**DIY 背包使用** | 按描述符 |

### 2.3 地址禁区

| 条款 | 要求 |
|---|---|
| 2.3.1 | 0x50～0x57 全部保留给身份卡。背包板上不得再放 `24Cxx` 族器件，也不得放其他占用 0x50～0x57 的器件 |
| 2.3.2 | 背包上其他挂在身份卡总线上的 I2C 器件地址须避开 0x50～0x57 |

### 2.4 身份卡器件

| 条款 | 要求 |
|---|---|
| 2.4.1 型号 | `AT24C02` 系列（容量 2 Kbit）。**禁止** 24C04／08／16：它们用地址脚做页选，会占用多个地址 |
| 2.4.2 写保护 | `WP` 须保护整片（选型时按手册核实）；`WP` 经 10 kΩ 上拉至 `3V3` 并引出测试点；烧写时短接（拉低）到 `GND`。**不得**把 `WP` 直接接地 |
| 2.4.3 速率 | 100 kHz |
| 2.4.4 地址脚 | `A0`～`A2` 须直接接 `GND` 或背包焊盘 3、4（`3V3`），不得悬空；DIY 背包 `A0`～`A2` 全部接 `3V3`（0x57）。经 0 Ω 选焊位连接时，设计文档须写明贴装状态与对应地址，回板时读地址核对 |
| 2.4.5 封装 | 须选 `A0`～`A2` 三脚全部引出的 8 脚封装（SOIC-8／TSSOP-8；放底面时用 TSSOP-8，见 SPEC-003 4.1）。SOT23-5 等 5 脚封装没有地址脚、地址固定，不得使用 |
| 2.4.6 存储区 | `0x00`～`0x0F` 为描述符区：烧录版（0x57）写 12 字节描述符，其余 4 字节保留。`0x10`～`0xFF` 为背包用户区：内容与格式由该背包设计文档定义，主机识别流程不读取；写入时短接 `WP` 测试点 |

## 三、product_id 与相关字段

本章字段写入烧录版（0x57）身份卡。

| 条款 | 要求 |
|---|---|
| 3.1 分配单位 | **一个型号一个 `product_id`**。同一型号的改版（V1.0 → V1.1）不换 `product_id`，用 `hw_ver` 区分；同一功能、主芯片不同的并行版本各用独立 `product_id` |
| 3.2 编号 | 16 位。`0x0000`（未分配）与 `0xFFFF`（空白 EEPROM 读出值）禁用。**`0xF000`～`0xFFFE` 为 DIY 号段**：自用、不保证全局唯一、无需申请。`0x0001`～`0xEFFF` 为全局唯一号，须按第四章申请，作废后不复用 |
| 3.3 `hw_ver` | 高 4 位为主版本、低 4 位为次版本（V1.0 = `0x10`、V1.1 = `0x11`、V2.0 = `0x20`）；版本号超过 15 时另行申请编码 |
| 3.4 `form_id` | 取值见 3.7。需要新形态时通过 Issue 提出，不在本规范内自行分配 |
| 3.5 其他字段 | `signature`、`spec_ver`、`flags`、`crc16` 见 3.6 |

### 3.6 描述符格式（12 字节固定偏移）

```
偏移   字段         宽度  说明
─────────────────────────────────────────────────────────
0..3   signature    4 B   ASCII "HuBo"
4      spec_ver     1 B   本规范版本，当前 = 0x01
5      form_id      1 B   复用区形态，见 3.7
6..7   product_id   2 B   型号唯一 ID（小端），仅 0x57 烧录版使用；
                          0x0000、0xFFFF 禁用
8      hw_ver       1 B   背包硬件版本：高 4 位主版本、低 4 位次版本
                          （V1.0 = 0x10、V1.1 = 0x11）
9      flags        1 B   bit0 = ESP_INT 极性（0 低有效 / 1 高有效）
                          bit1 = PACK_PEN（1 = 焊盘 28 为本背包使能脚）
                          bit2~7 保留，须写 0
10..11 crc16        2 B   CRC-16/CCITT-FALSE，覆盖偏移 0..9（小端）
─────────────────────────────────────────────────────────
                    12 B  全部
```

- CRC-16/CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，覆盖偏移 0..9，结果按小端写入偏移 10..11。
- EEPROM `0x00`～`0x0F` 为描述符区（12 字节描述符 + 4 字节保留，保留字节烧写为 `0xFF`）；`0x10`～`0xFF` 为用户区（2.4.6）。
- 多字节字段小端。
- **主机遇到不认识的 `form_id` → 按 `0x00` 处理**（复用区全高阻），不报错。
- **`spec_ver` 高于主机支持的版本 → 只按已知字段解析**；偏移 0..11 的含义在后续版本中不得改变（仅可在其后追加）。
- `flags` 的保留位不为 0 → 忽略，不影响解析。
- **`flags.bit1 = 1`：焊盘 28（主板 `U1-27`）是本背包的使能脚（`PACK_PEN`）**——主机在描述符校验通过后，把该脚配为输出并拉高，不论 `form_id`。使能对象可以是背包电源（背包侧须经负载开关门控），也可以是某项功能（如功放使能）；背包侧使能脚须有下拉，保证主机拉高前默认关断。`bit1 = 0` 时该脚按 `form_id` 处理。`form_id = 0x03`（LoRa）与 `form_id = 0x04`（并行输入）的背包 `bit1` 必须为 0（该脚分别为 `BUSY` 输入与逻辑分析输入，主机驱动会对驱）。

### 3.7 `form_id` 取值

| 值 | 形态 |
|---|---|
| `0x00` | **不使用复用区**（8 针全部保持高阻） |
| `0x01` | SPI |
| `0x02` | I2S（音频） |
| `0x03` | LoRa（SPI + 控制线） |
| `0x04` | 并行输入（8 路逻辑分析，8 针全部为主机输入，主机不驱动） |
| `0x05` | SPI 从机 + UART + 就绪握手（适合带独立处理器的背包；焊盘 28 为 `PACK_PEN`） |
| `0x06`～`0xFF` | 预留，需要新形态请提 Issue；主机按 `0x00` 处理 |

复用区各针的用途随 `form_id` 而定，主板侧只称其为复用区 GPIO（针位见 SPEC-003 3.1）。每针可承担的功能见 SPEC-003 3.1 下的接口定义图；各形态的完整时序与方向约定本公开版不含。

### 3.8 开发者怎么选

1. **地址**：`0x50`～`0x56` 为官方型号保留（免烧录），DIY 一律用 `0x57` 烧录版。
2. **`product_id`**：DIY 用 `0xF000`～`0xFFFE`，无需申请；需要全局唯一号，到本仓库提 Issue。
3. **`form_id`**：按复用区 8 根线的用法从上表中选，主机固件据此配置这几根线；都不合适就选 `0x00`，在 USR 网络上自行使用；需要新形态请提 Issue。

## 四、申请流程

### 4.1 时机

通过 Issue 申请全局唯一 `product_id` 的，须在**原理图冻结前**完成申请，并写入该背包的设计文档。DIY 号段（`0xF000`～`0xFFFE`）无需申请。

### 4.2 步骤

| 步 | 动作 | 负责 |
|---:|---|---|
| 1 | 在本仓库按 [Issue 模板](../../.github/ISSUE_TEMPLATE/product-id-request.md) 提交申请：背包名称、功能与 `form_id`、身份卡总线上其他 I2C 器件及地址（须避开 0x50～0x57）、首版 `hw_ver`、项目链接 | 申请人 |
| 2 | 维护者核对 `form_id`、地址与主机固件识别逻辑一致，在 Issue 中回复分配的 `product_id` | 维护者 |
| 3 | 将 `product_id` 写入设计文档和原理图身份卡旁的注释 | 申请人 |

### 4.3 变更与作废

- 项目取消：编号作废，不复用；
- 改形态（`form_id` 变化）：视为新型号，重新申请；
- 改版：同一 `product_id`，用 `hw_ver` 区分。

### 4.4 免烧录地址与查表值（分配与变更）

（本公开版不含）

### 4.5 DIY 背包

- 使用 0x57 烧录版，`product_id` 取 `0xF000`～`0xFFFE`，自行选定，无需申请；该号段不保证全局唯一，不同人的背包可能重号。
- 需要全局唯一号时按 4.2 提交 Issue。
- 主机固件对不认识的 `form_id` 按 `0x00` 处理、不报错，所以 DIY 号段不需要固件改动。

## 五、烧录版烧写

本章条款适用于全部 0x57 烧录版身份卡，DIY 背包必须按本章烧写。

| 条款 | 要求 |
|---|---|
| 5.1 内容 | 用 hubo-backpack-skill 中的 `idcard_image.py` 按 `product_id`、`form_id`、`hw_ver` 等生成 16 字节镜像（12 字节描述符 + 4 字节 `0xFF`，含 CRC），不得手工拼写；每款背包烧写自己的内容，不得沿用他人内容 |
| 5.2 写保护 | 烧写时将 `WP` 测试点拉低（短接到 `GND`），烧完释放 |
| 5.3 校验 | 烧写后读回 12 字节，核对 `signature`、`product_id`、`crc16` |
| 5.4 烧写方法 | 用通用 I²C EEPROM 烧录器，把镜像写到 0x57 的偏移 `0x00` |
